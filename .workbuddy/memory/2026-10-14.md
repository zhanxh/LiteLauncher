# 2026-10-14

## ① pomo 挂件悬停伸缩：窗口必须真缩，不能只藏按钮
用户反馈：悬停才显示按钮已经生效，但**按钮区域还占着宽度**，组件没有缩短。

- 根因是昨天的决定反过来咬了一口：挂件**不能依赖窗口透明**（WebView2 真机露白底），
  所以"窗口矩形 = 卡片本身"。CSS 里把按钮 `display:none` 只会留一块同色空白，
  窗口尺寸不变 → 用户看到的"按钮区还在"就是这个空白。唯一解是**真改窗口尺寸**。
- 新纯函数模块 `plugins/pomo/fe/src/hover-size.ts`：常量全部**由布局部件推导**
  （`COLLAPSED_W = PAD_X*2 + RING + GAP + LABEL_W = 186`、
  `EXPANDED_W = … + LABEL_W_HOVER + GAP + MAX_BTNS*BTN + 间距 = 300`）。
  写死数字的话，加一个按钮/改一次标签宽度就会漂移到"切掉按钮"或"留大块空白"。
- 伸缩方向选**右边缘钉住、向左生长**：挂件停右上角、离屏幕右边只有 16px 余量，
  向右扩会把按钮推出屏幕。代价是收拢时环和标签右移，用 170ms `easeOutCubic` 掩盖。
- 每帧由**动画开始时读一次的基准**（右边缘/顶边/起始宽度）推导，不在帧内再查询——
  否则读到"上一条 setSize 还没生效"的中间值会累积误差。
- `animToken` 令牌：快速划过时两段动画会并发写尺寸互相拽（表现为抖动或停在半开）。
  `beginDrag` 里也要先作废动画再 `startDragging`，否则动画用的是**拖动前**的右边缘，
  窗口会被拽回旧坐标 → 用户体感"拖不动/弹回"。
- capabilities 补 `core:window:allow-set-size` / `allow-set-position`（漏了会静默失败）。
- **三处对齐**：hover-size 常量 ↔ `manifest.views[0].width/min_width`（186/176，
  min_width 必须 ≤ 收拢宽度，否则 `set_size` 被 `min_inner_size` 夹住，
  表现为"代码在动、窗口不动"）↔ `widget.css` 的 `.pw-label` 宽度。
  测试直接把后两者当文本读出来比对，见 `test-fe-plugins.mjs` 的 hover 用例。

## ② Windows 上所有 Python 插件都弹控制台窗
- 根因：GUI 进程（Tauri）启动控制台程序时，系统会**给它新建一个控制台**并抢焦点 →
  输入框失焦，多个插件 = 多个黑窗。
- 修在集中点 `ll-host/src/python.rs::hide_console`（`CREATE_NO_WINDOW = 0x08000000`），
  `llp.rs` 启动 sidecar 与 `run_capture`（探测解释器）都走它 → 覆盖全部 LLP 插件。
- 平台差异用 cfg 双实现吸收，非 Windows 是空函数（子进程本来就没有控制台）。
  注意签名必须是 `hide_console(mut cmd: Command) -> Command`（按值），
  不能写 `&mut Command`——Rust 不能对临时值隐式取 `&mut`。
- 不影响 LLP 的管道协议（stdin/stdout 仍是管道，只是没有可见控制台）。

## ③ ll-host 在 Windows 编译十几分钟：profile 问题，不是代码量
- 用户进度条停在 `504/506: tauri-app` —— 500 多个依赖早就编完了，
  剩下的时间**全在最后两个编译单元**，正是 fat LTO 全图重优化 + 单 codegen unit。
- 方案（用户选③）：`[profile.release]` 降到日常档 `lto = "thin"`、`codegen-units = 4`；
  发布档用**命令区分**而不是改 Cargo.toml —— `build.cmd ship` / `build.sh ship`
  用 `CARGO_PROFILE_RELEASE_LTO=true` + `CARGO_PROFILE_RELEASE_CODEGEN_UNITS=1`
  环境变量覆盖，并把 `CARGO_TARGET_DIR` 指到独立的 `src-tauri/target-ship`，
  这样换档不会作废日常增量缓存（两个档各自的缓存互不干扰）。
  判据一句话：自己看效果 → `build.cmd`；要发给别人的那个 exe → `build.cmd ship`。
- README 第 3 节同步改了，并修掉一处过期产物名（`tauri-app.exe` → `LiteLauncher.exe`）。

## ④ pomo 分段循环：专注↔短休 5:1 + 自动衔接开关
用户原话要点：`专注+短休结束后，有个按钮点击可以重新开始，不是一直循环，专注:短休 = 5:1`；
`人工点击按钮启动下一轮，勾选自动后自动开始下一轮；初始 add 后就是自动勾选`。

落地：
- **sidecar 状态机**（`pomo.py`）：`_state` 加 `phase/focus_label/focus_minutes/break_minutes/
  auto/hold/next_phase/rounds`。`_worker → _on_phase_end(phase)`：auto=1 直接 `_start_phase(下一段)`，
  auto=0 置 `hold=1` 并落盘等人工。`_start_phase` 短休用 `break_minutes`/标签"短休"，
  专注用 `focus_minutes`/`focus_label`（否则短休结束会变成默认 25 分钟）。
  `_start_new` 里 `auto=True` —— "初始 add 就勾选自动"。
  新增动词 `next`（hold→下一段）与 `auto:on|off`；`_set_auto(True)` 若正 hold **立即接上**。
- **`hold` 是新状态，不是 idle**：上一版到点只把 `target` 清零，挂件读到 target=0
  就退回 IDLE_VIEW → 用户看到「25:00 准备开始」，以为倒计时从没跑过（本次反馈的原型）。
  `_remaining()` 单列 `"hold"`，`_status_items()` 单列一屏（`pomo:next`/`pomo:auto`/`pomo:hold`）。
- **跨进程数据改为单键 `snap`**：`_persist` 写 `snap = json.dumps(_state)`，挂件每秒读一次。
  原来是每秒 4~9 趟 `settings.get`（每趟 webview→宿主→SQLite），且分次读会读到**撕裂态**。
  散装键全部保留：面板/命令按名取值，同时是 snap 缺失（旧版本残留/JSON 写坏）时的回退源。
  回退路径经 `stateFromParts()` 归一成同一个 `WidgetState`，渲染层不分叉。
- **挂件 UI**：悬停区最多 3 个按钮 = `↻ 自动衔接`（勾选态 `.pw-btn--on`）+
  当前动作（`❚❚` 暂停 / `▶` 继续 / `▶` 开始下一段，三者互斥）+ `✕`。
  `MAX_BTNS=3` 是展开宽度的依据，加按钮要同步改它。
  hold 态环心显示「待开始」、进度环走满，标签只说「已完成 N 轮」，
  「点 ▶ 开始短休」放在第二行 —— 第一行 84px 收拢宽度会把长句截成省略号。
- **5:1 两侧各写一遍 = 会各错一遍**：`timer.ts::breakMinutesOf` 与
  `pomo.py::break_minutes_of` 必须同结果，测试双向钉死（读对方源码比 BREAK_RATIO，
  并对 5/7/25/30/45/60/90 逐值对齐）。整数输入下不会出现 .5 平局，
  所以 JS `Math.round`（.5 向上）与 Python `round`（.5 向偶）在这里不会分叉。

## ⑤ Linux 首构建：两个缺库（都不是代码问题）
- bindgen 报 `Unable to find libclang`：`xcap → libspa-sys / pipewire-sys` 要 libclang →
  `sudo apt install libclang-dev`。装完不用设 `LIBCLANG_PATH`（包会把 `libclang.so`
  放进 `/usr/lib/x86_64-linux-gnu/`，bindgen 自己能找到）。
- 链接报 `unable to find library -lgbm`：机器上只有运行库 `libgbm.so.1`，缺 dev 符号链接
  → `sudo apt install libgbm-dev`。Debian 12 上 Tauri 还常缺一组 webkit 开发包：
  `libwebkit2gtk-4.1-dev librsvg2-dev libsoup-3.0-dev libjavascriptcoregtk-4.1-dev`。
- 判据：报 `Unable to find libclang` = 缺 `-dev`，不是版本/代码问题，别去改 build.rs。

## ⑥ `/qr 打开二维码图片`失败：URL 被"路径黑名单"误杀
- `HostProcessApi::launch` 原先对 target 一律套 Shell 注入元字符黑名单，其中含 `&`；
  二维码链接 `…?size=320x320&data=…` 正好带 `&` → 直接 `bad_params`。
  `/dict` 的 URL 没有 `&`，所以这个坑藏了很久才暴露。
- 修法是**按目标类型分策略**，不是放宽黑名单：URL 走 `validate_url_target`
  （放行 `& ? = % #`，仍拒引号 / `$` / `|` / `<>` / 反引号 / 空白 / 控制字符，
  且要求解析得出 authority，`file://` 例外）；可执行路径与裸命令走 `validate_path_target`
  （原黑名单一字不改）。
- ⚠️ **放开 `&` 必须同步改 Windows 分支**：URL 原先走 `cmd /c start ""`，`&` 在那里
  真是命令分隔符，而 Rust 只给含空格的参数加引号 → 不同步改就是真注入洞。
  现在 URL 走 `rundll32 url.dll,FileProtocolHandler`，不经 shell。
- 教训：安全校验按"字符危不危险"一刀切，会把合法输入一起挡掉；
  正确的判据是**这个目标最终会不会进 shell**。

## ⑦ GTK 把小窗口撑成 200×200（挂件在 Linux 上多一圈底色）
- 现象：manifest 声明 186×88，`xwininfo` 实测 200×200；
  `WM_NORMAL_HINTS` 为 `base 176×88 / min=max 200×200`（min=max 是 `resizable:false`
  把 hint 钉死，base 才是我们声明的 `min_inner_size`）。
- 链路：wry `WebViewAttributes::default()` 的 `bounds = Some(200×200)`，而 tauri 稳定 API 的
  `WebviewWindowBuilder` 路径**不设 bounds**（只有 `unstable` 分支才
  `with_bounds(window.inner_size())`）→ 默认值生效 → `GtkWindow` 不能缩到子控件尺寸请求
  以下 → `inner_size(186,88)` 被夹成 200×200。Windows 无此下限，所以两边形状都不一样。
- 修在宿主集中点 `services.rs::clamp_gtk_child_min_size`（Linux 专用，建窗后、
  角落定位**之前**——定位按 spec 尺寸算，窗口被撑大时两者就对不上）：
  把窗口子控件的 `set_size_request` 压回视图声明的 `min_*`，再 `set_size` 回 spec。
- ⚠️ 只压到 **`min_*` 而不是 spec**：挂件悬停要扩到 276 宽，下限取最小值才不会挡住 resize。
  `set_size_request` 只是最小值，子控件照样被分配整个窗口，所以撑大的场景不受影响。
- 依赖：`ll-host` 加 Linux 目标 `gtk = "0.18"`，必须与 Tauri 内置同版本（否则出现两份
  互不兼容的绑定）。`WebviewWindow::gtk_window()` 是内建方法，不需要 `WindowExtUnix`。

## ⑧ Linux 上"字比 Windows 小许多"：会话没开缩放，不是插件问题
- 挂件字号 15/12px、主搜索框 18px，量级都正常；窗口按逻辑像素建，HiDPI 换算宿主也做了
  （`services.rs` 全屏遮罩那处明确除过 `scale_factor`）→ 尺寸跟随系统缩放是**设计如此**。
- 本机实测：X11 + 2560×1600 / 344mm ≈ **189 DPI**，但 `scaling-factor=0`、
  `text-scaling-factor=1.0`、`Xft.dpi=96` → 1 逻辑像素 = 1 物理像素。
  同一块屏 Windows 会自动推荐 150%~200%，于是同一句 CSS 在 Linux 上小一半到两倍。
  主窗口实测 680×260 物理像素（占屏宽 26%）就是证据。
- 结论：要观感一致就在**系统侧**开缩放（`GDK_SCALE=2` 或 GNOME 缩放因子 2）。
  在 app 里补偿会双重放大，是错的方向。
