# 2026-10-15

## ① 从"查看详情有标题栏"到一个宿主能力：弹出式基窗
起点是一个很小的疑问：`/cal` 的提醒卡没有窗口外壳，「查看详情」「编辑日程」却有一条系统标题栏。
差别只在一个字段——`plugins/todo/manifest.json` 里 `detail` 声明 `decorated:true`、`reminder` 声明 `false`，
宿主原样透传给 Tauri 的 `.decorations()`。用户要的不是"把这个窗口改掉"，而是
**把「无边框 + 可拖拽 + 高度跟随内容」下沉成宿主通用能力**，插件在 manifest 声明、前端放进 widget 就得到弹窗效果。
已确认的三个取舍：**实心窗口 + 系统圆角**、**全量收编**（详情/提醒/pomo/pick）、
**长内容走内部滚动 + 可见滚动条**（等于接受 `resizable:false`）。

四条已经付过代价的约束：
- **像素换算与锚定只在宿主做**。`ll-plugin-api` 里新增四个纯函数
  （`popup_policy` 归一化 min/max 区间，冲突时收敛到 max、绝不产出反向区间；
  `popup_rect_after_size` **按当前矩形的边**锚定——center/右上钉顶边、右下钉底边、右上挂件改宽钉右边，
  再把矩形夹回 `[CORNER_MARGIN, mon-size-CORNER_MARGIN]`；`window_label` / `label_matches_view`）。
  按"当前矩形"而不是重算显示器边缘，才扛得住用户拖过的窗口和多屏。
  ⚠️ `window_label` 必须**同时**用于建窗和校验：分成两处就会漂移，而这是那条权限检查唯一能被绕过的途径。
- **调用者身份由 Tauri 注入，不由插件声明**。`commands.rs::plugin_call` 加 `window: tauri::WebviewWindow`
  参数（`WebviewWindow` 实现了 `CommandArg`，拿到的就是发起这次 IPC 的窗口），`dispatch_svc` 收 `caller: Option<&str>`；
  sidecar（`llp.rs` 的两条 stdin/none 路径）传 `None` 直接拒。于是**"改一个不属于我的窗"在协议层就表达不出来**，
  和 `SettingsApi` 强制前缀、Secret 归属校验是同一套路子。
- **拖拽不要用 JS 手写**。Tauri 2.12.2 已经注入了 `drag.js`：`data-tauri-drag-region="deep"`
  让子树任意位置可拖，`isClickableElement()` 自动跳过 button/input/a/`[tabindex]`/role=button。
  原先三处手写 mousedown→`closest('.xxx-actions')`→`startDragging()`（提醒卡、pomo 挂件、主搜索框）全部删掉。
- **自适应高度要和系统最小值打架**：`min_inner_size` 只在 `min_width` 与 `min_height` **同时**声明时生效（两个都得写）；
  `clamp_gtk_child_min_size` 原先拿 `min_height.unwrap_or(spec.height)` 当 GTK 子控件下限，
  auto_height 下不改成 `POPUP_MIN_H_FLOOR`(96) 就**在 Linux 上永远缩不回去**。
  `stacked` 的堆叠偏移也从"累加声明高度"改成**累加实际高度**，否则内容自适应的卡片第二个会压住第一个。

## ② 自激棘轮：测量的必须是内容的自然高度，不是窗口高度
把窗口高度设成内容高度、又用窗口高度当测量目标，就是一个正反馈环：长高→内容更高→再长高，停不下来。
终态是 **body 当滚动容器**：`body.ll-popup-mode{height:100vh!important;overflow:auto!important}` +
`#root{height:auto!important}`，卡片自身一律不写 `height:100vh`（`min-height:100vh` 同样禁止）。
`reminder.css` 里 `.reminder-card` 原来是 `height:100vh`，这就是最容易漏的一处。

CSS 侧还有一层必须先看清再动手：`index.html` 给 `html,body,#root` 写死了
`background-color:#1a1d24 !important` 并全局隐藏滚动条。所以弹窗样式**必须同样带 `!important`** 才压得住；
顺带发现旧的 `body.detail-mode` 那条没加 `!important`，也就是说浅色主题下详情窗一直是
"白卡片坐在深色底板上"——它本来就没生效过。作用域用 `body.ll-popup-mode`（不是 documentElement）：
(0,1,1) 对 (0,0,1) 同带 `!important` 时胜出，且 `html` 保留 `overflow:hidden` 才不会出现双滚动条。

## ③ mountPopup 的两条防抖：死区与拖拽挂起
`plugins/sdk/src/popup.ts`（**纯 `.ts`、不依赖 solid**，能被 Node 直接跑——和 pomo 的 `hover-size.ts` 同思路）：
- `ResizeObserver` → `Math.ceil(rect.height)`，每 rAF 合并一次写，**2px 死区**（沿用主窗口 `App.tsx` 的约定）。
  没有死区时字体换行/亚像素取整会让高度在 200/201 之间来回发 IPC。
- **拖拽期间挂起上报**：元素 mousedown → 一直到 window 上的 mouseup 都不发尺寸。
  元素的 handler 早于 Tauri `drag.js` 的 document 冒泡 handler，这是干净的挂起点。
  这条是把 pomo 当初"拖动时动画把窗口拽回旧坐标（体感弹回）"的教训一般化。
- `isHostAvailable()` 为 false（vite 预览）时照常加类、照常测量，只是不发 IPC。

pomo 是**宽度**驱动（悬停展开/移开收拢），改完只剩 `lerp`/`easeOutCubic`/常量，
`frameAt`/`leftEdgeOf`/`HoverFrame` 三个几何函数**删掉了**，每帧只发 `setContentSize({width})`，
锚边交给宿主；`animToken` 的"新动画作废旧动画"与拖动前 `settleBeforeDrag` 保留——那是插件侧策略，不是几何。
pick 取色台**故意不接 auto_height**：放大镜随滚轮缩放会变高，等于在用户眼皮底下改窗口尺寸，
而面板 body 的 mousedown 已经是"单击取色"，只收编了拖拽属性。

## ④ EventModal 加 `variant`，而不是复制一份编辑表单
详情窗里就地编辑，复用日历窗内那套浮层表单：`variant?: 'overlay' | 'inline'`（默认 `overlay`，日历窗行为一字不变）。
`inline` 时不套 `.cal-modal-mask`、不要 `calc(100vh - 48px)` 上限、`.cal-modal--inline` 把边框/圆角/阴影/底色全清掉
（窗口本身已经是卡片），高度上限交给 `max_height` 与窗口内滚动。只读↔编辑切换时 ResizeObserver 自然重测，
顶边钉住 → 标题行不动。
`PopupFrame` 的 `.ll-popup-body` **刻意不加 padding**：内边距会让插件自己的 body/foot 分隔线缩进不到卡片边缘，
内部间距归插件 CSS 管。不传 `title` 时子内容自带头部——详情/编辑要在标题行放「编辑」「删除」，那是插件 UI 不是壳 UI。

## 真机验证（本机 Linux/X11 已跑过一半）
`cargo run`（debug，走遗留的 1420 vite dev server）起来后，日志与 X 实测拿到的证据：
- **pomo 宽度链路端到端通**：`lifecycle.log` 里 `pomo-widget` 的 Resized 序列走完 186→306→186，
  静止态 `x+width = 2358+186 = 2544 = 2560-16` —— **右边缘由宿主钉住、顶边 y=16 全程不动**，
  正是 `popup_rect_after_size` 的承诺。
- **但真机量出一个缺陷并修掉了**（这是本次唯一只有真机才看得出来的东西）：
  动画途中 `x+width` 在 2544~2569 之间跳（±12~25px），停下来才归位。
  根因是 `apply_content_size` **每帧从窗口读基准矩形**，而 `set_size`/`set_position` 要等 WM 处理才反映到
  `outer_position()/outer_size()` 上 —— 每帧读到的都是"尺寸已更新、位置还没更新"（或反之）的半成品。
  旧实现靠"动画开始时读一次基准"躲过了这件事，下沉到宿主时把这个性质丢了。
  修法是宿主记住**自己上一次请求过的矩形**（`last_requested_rect` / `remember_rect`，按 label 存，TTL 500ms）：
  尺寸还没追上请求 = 在途 → 用请求过的矩形续算；尺寸一致 = 已落地 → 立刻回到实时读数
  （这样用户把窗口拖走后不会被拽回旧坐标）。选择规则抽成纯函数 `baseline_rect` 并单测
  （`cargo test -p ll-host` 19 例）。
  ⚠️ 教训：**"锚定基准从哪儿来"是语义的一部分，不是实现细节**。把几何计算搬进宿主时，
  必须把旧代码"一次性读基准"这个隐含约定一起搬，否则单元测试全绿、真机一路抖。
- **`@ll/ui` 里的 `.tsx` 确实被 solid 编译**：`curl :1420/plugins/ui/src/PopupFrame.tsx` 返回的是
  `createComponent`/`_tmpl` 转译结果，`popup.css` 200，`EventDetail.tsx` 正常引到 `PopupFrame`。
  计划 §8 列的那条风险到此排除。
- **dev server 服务的是新代码**：`curl :1420/plugins/pomo/fe/src/widget.tsx` 里只有 `.setContentSize(`，
  没有 `setSize`/`setPosition` —— 上面的几何证据确实出自新链路而非旧包。
- 两次启动（21:12 与 21:24）以来日志**无 FE 报错、无建窗失败**。
- 仍未看过的一眼：**提醒卡与详情窗**（要人操作 `/cal`：本机没有 xdotool 之类注入键鼠的工具，
  也没有 headless 浏览器，pomo 挂件重启后也没法自己弹出来）。需要实测的项：无标题栏、拖标题行可移、
  高度贴合内容、浅色主题四角干净、编辑态长高时顶边不动、长备注停在 `max_height` 且有可见滚动条、
  拖拽中改内容松手不弹回、多详情窗 + 两张提醒卡叠放不错位，以及**修复后的确认项**：
  悬停伸缩全程 `x+width` 恒为 2544。
  **Windows 发版前必查**：1px DWM 白边是否已由 `!decorated` 去掉、开窗无白闪
  （`visible(false)` + `POPUP_REVEAL_GRACE_MS=1200` 兜底 show）、`data-tauri-drag-region` 与 WebView2 无冲突、
  HiDPI 125% 下上报高度与 `window.innerHeight` 一致。
  **Wayland**：`set_position` 归 compositor，角落锚定可能静默失效，按 `attachDesktop` 的"如实降级"惯例处理
  （已写进指南 §5.6）。

## 真机验证跑完（X11 + XTEST 注入键鼠，本机做得到）
上一节说"没有注入键鼠的工具"是错的：python3 `Xlib` 0.33 的 `Xlib.ext.xtest.fake_input` 就能发点击/滚轮，
`import -window <id>` 能按窗口截图。据此把详情窗、提醒卡、叠放、`max_height` 全部实测了一遍，
**量出并修掉三个只有真机才看得出来的缺陷**：

1. **GTK 忽略不可 resize 窗口的应用侧 `set_size`，而 Tauri 返回 `Ok(())`**。症状：前端在报 160，
   窗口停在声明的 182，卡片下面一条没画过的空白（用户原话"窗口下方多了一行白色空白处"）。
   修法：`let resizable = if spec.auto_height { cfg!(target_os = "linux") } else { spec.resizable }`，
   并给 `mountPopup` 加 `window.addEventListener('resize', queue)` —— 用户真拖了边框就弹回内容高度。
   ⚠️ 单测与 `cargo check` 对此完全无感，只有 X 侧量窗口几何才发现 `set_size=Ok(())` 而窗口没动。
2. **`index.html` 的 `html, body, #root { color:#f3f4f6 !important }` 是 ID 权重 (1,0,0)**，
   压过 `body.ll-popup-mode`(0,1,1)。底色/字色写在 body 上会被 #root 挡回去：
   `.cal-detail-title` 没自己声明 color → 浅色主题下"日程详情"四个字白到看不见（用户原话"没有之前的美观、
   和提醒不是同一配色"）。修法：`body.ll-popup-mode > #root` 上重写 height/background/color。
3. **`stacked` 偏移读的是 `outer_size()`，而 auto_height 窗口建出来是 `visible(false)`：
   GTK 对未映射窗口返回 0** → 五张提醒卡只各自偏移那条 8px 间隙，实测两张卡 y 只差 8（完全叠在一起）。
   修法：宿主自己记一张 `content_height_memory`（label→逻辑高，建窗时先填声明值），叠放按它累加。
   顺带发现 **GTK 在 `set_size` 落地时会回放它自己记住的位置**，把紧随其后的 `set_position` 覆盖掉
   （底边锚定的卡缩高后 y 停在旧值）→ 加 `reassert_position`：120ms 后确认"尺寸已落地且这条请求
   仍是该 label 最新一笔"才补一次位置。⚠️ `unique_by` 的窗口销毁重建后 **label 一模一样**，
   补偿线程必须校验窗口还在 + 记账未被新请求覆盖，`open_on_main` 建窗时要清掉旧 label 的矩形/高度记账，
   否则会把新窗口拽到旧窗口的坐标上（真机见过详情窗"自己往鼠标方向挪"）。

另外确认：详情窗 440x355 贴合内容、编辑态长到 657 且**顶边不动**、取消缩回 355；长备注停在
`max_height=720` 并可滚；标题行改成 `position: sticky`（用户："窗口标题不滚动"—— 滚的是 body，
不钉住标题就跟着滚走）。回归里补了三条断言（`> #root` 的 color、`.ll-popup-head` 的 sticky、
services.rs 里 `resizable = if spec.auto_height { cfg!(target_os = "linux") }`），
`tools/test-fe-plugins.mjs` 的 `#root` 正则原来只认后代写法、不认 `> #root`，已放宽。
