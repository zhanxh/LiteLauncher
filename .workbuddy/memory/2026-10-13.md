## 插件规划（plugin roadmap）
- 产出 `docs/plugin-roadmap.md`：盘点"常用插件候选 + 按宿主能力门槛分层"。

- 建议批次：① 纯计算工具季（hash/text/json/rand/ts/unit/color/cidr）② 补 clipboard + svc:* 前端形态 ③ 补 hotkey + 屏幕捕获后上 截图/取色器/剪贴板历史。

## 实现形态选型（内置 Rust vs Python/LLP）
- 已补入 `docs/plugin-roadmap.md` §6。
- 关键机制：LLP 外部插件前端零代码——`src/core/externalPlugins.ts` 按 manifest 的 `command` 声明自动生成通用 `CommandPlugin`；参数自动映射 execute→{raw,subcommand,args,namedArgs}、search→{keyword,subcommand,args}、select→{id,metadata}。
- 内置 Rust：7+ 文件 + 3 处宿主接线 + 重编译主程序；无运行时依赖。LLP：2 文件（manifest.json + .py）+ 拷目录即装，但依赖目标机有 Python 3、不支持自定义 UI 窗口、串行会话 5s 超时、每插件常驻一个解释器进程。
- 结论：核心高频工具（含 `/hash`）→ 内置 Rust（零依赖、可进单 exe）；探测/可选/第三方（如 sysinfo）→ LLP Python；长期等 `svc:*` 纯前端形态收口。可用 LLP 快速试水 UX 再移植 Rust。

## 术语校正（重要）
- 用户明确：本项目**一切皆插件，不做"内置"**（所有功能走插件机制，禁止硬编码进壳层/宿主）。
- 注意仓库文档的既有叫法：开发指南 §1 把 `plugins/*/be`（随主程序编译、lib.rs 注册的 Rust 插件）称为**"编译期内置插件"**——这与用户口语里的"内置"含义冲突。已把 roadmap §6 标题/正文改为**"编译期插件（Rust）vs 外部插件（LLP）"**，并加术语对齐说明。
- 洞见：**LLP ≠ Python**——`backend.entry` 可指向任意可执行文件（支持 `node`、绝对路径），故外部插件也能用 Rust 编的独立二进制（零运行时依赖）；"用 Rust"也不等于"编译进主程序"。

## 宿主能力补齐（4 项，全部落地）
1. **`svc.db.migrate`** —— 兑现 `DbApi::migrate`（`execute_batch`），只对插件自己的库生效（`plugins/<id>/<id>.db`），故放行 DDL 无越权。
2. **`svc.clipboard.write/read`** —— 新增 `ll_plugin_api::ClipboardApi` + `PluginContext.clipboard`；宿主实现走 **`tauri-plugin-clipboard-manager` 2.4.2（底层 arboard）**，不用 webview 剪贴板。**写/读分权**：`clipboard:write` / `clipboard:read`。壳层 `AfterSelect.copy` 同步切到宿主命令 `clipboard_write`（`src-tauri/src/lib.rs`）。
3. **`svc.http.send`** —— 借道 `HttpApi::send_stream` 收集全文，**顺带拿状态码**，返回 `{status, body}`；仍走 `net:<host>` 白名单。`headers` 兼容 `{"K":"V"}` 与 `[["K","V"]]`。
4. **`svc:*` 纯前端插件形态（`backend.kind="none"`）** —— 三处协同：
   - 宿主：`handle_svc` 提炼为公共 `services::dispatch_svc`（LLP 反向请求与前端 `ctx.call('svc.*')` **共用同一分发器**）；`plugin_call` 把 `svc.*` 当**宿主保留方法名空间**优先拦截，不查后端分发表；新增 `SvcBackend`（kind=none）；`register_external_plugins` 接受 `kind="none"`。
   - 权限门控：已注册插件按 `manifest.permissions`；未注册（只随前端包编译进来）退回 `shell_safe_manifest`（仅 settings/clipboard:*/notifications/events，**db/process/net 一律拒绝**）。
   - SDK：`ctx.settings/clipboard/log/notify/events` 同名属性包装 `svc.*`；新增 `isHostAvailable()`。
   - 开发期宿主 `#[cfg(debug_assertions)]` **自动扫描仓库 `plugins/`**（`env!("CARGO_MANIFEST_DIR")/../plugins`），免每次 plugin:install，且让 kind=none 能读到 manifest。
   - 工具：`install-plugin.mjs` / `deploy-portable-plugins.mjs` 支持 kind=none（**只部署 manifest.json**，fe 已在应用包内）。

- 形态：既然 `svc.http.send` 已落地，网络类**无需 Python**，全部做成 `kind=none` + `fe/src/index.ts`，仅 `manifest.json` 声明 `net:<host>`。零宿主改动、零重编译。

## 落地：D 组能力包（屏幕捕获 + 全局热键）+ `/shot` `/pick`
- 宿主新增两项能力：`ScreenApi`（`screen` 权限，xcap 0.9 + image(png) + Tauri `AppHandle::cursor_position()`）与 `ShortcutApi`（`shortcut:<accel>` 权限，tauri-plugin-global-shortcut + 宿主自建仲裁表）。`PluginContext` 增 `screen` / `shortcuts`。
- `dispatch_svc` 新增：`svc.screen.list|cursor|pixel|capture`、`svc.shortcut.register|unregister|list`、**`svc.window.open`**（纯前端插件唯一的开窗途径）。`PluginErrorCode` 增 `Conflict`。
- **热键协议**：宿主按 `shortcut:<accel>`（逐条、无通配）放行 → 进程级 `accel→pluginId` 表先到先得仲裁（冲突回 `conflict`）→ 触发时 `emit("plugin-shortcut", {pluginId, accel})`。插件只听事件，拿不到按键流。解析/挂载失败都回滚登记。白名单校验放在 `AppHandle` 校验之前，便于无 GUI 单测。
- **关键坑（务必记住）**：纯前端插件新增视图窗口（标签 `<pluginId>-<viewId>`）**必须**同步加进 `src-tauri/capabilities/default.json` 的 `windows` 白名单，否则该窗口权限为零 → `plugin_call` 被拒、面板变死窗。本轮加了 `pick-*` 与 `core:window:allow-outer-position`/`allow-outer-size`。
- **坐标系**：对外统一桌面全局物理像素；但 `xcap::Monitor::capture_region` 要的是**显示器内相对坐标（u32）**，所以宿主先 `hit_rect` 定位显示器再减原点（这层换算不能散到插件里）。`x()`/`y()` 是 i32、`width()`/`height()` 是 u32。
- **截图避让**：`hideWindows:true` → 隐藏所有可见 LiteLauncher 窗口 + 额外 160ms 合成器宽限 → 截图 → 复原并回焦。`delayMs` 宿主硬上限 10s。
- **放大镜不传图片**：`svc.screen.pixel {radius}` 回 `#RRGGBB` 方格数组（`cols/rows/cells/center`，贴边自动裁剪），前端 CSS 网格铺出来即硬边像素放大；省掉 PNG 编码 + base64（约 33% 膨胀）。半径上限 32。
- **SDK**：`ctx.screen`（list/cursor/pixel/capture）、`ctx.shortcuts`（register/unregister/list/**on**）、`ctx.windows`（open）。**`ctx.shortcuts.on(accel, cb, {scope})` 默认 `scope:'main'`**——每个窗口加载都会跑一遍全部插件 `setup()`，不区分上下文则热键会被执行两次；取色台显式传 `{scope:'any'}`。
- **多窗口协同**：取色台与主窗口是两个 JS 上下文，靠插件私有 KV 共享（`pick.history`、`pick.panelOpen`）；面板开着时主窗口热键处理器读到 `panelOpen` 就让位，避免一次按键既复制又关窗。
- **取色台冻结**：`outerPosition/outerSize` 与 `svc.screen.pixel` 回传的采样坐标比对，光标进面板即停采样（否则采到面板自身颜色）。一次宿主调用同时拿到位置+颜色+放大镜，7Hz 轮询。
- 插件：`/shot`（主项=光标所在屏 + 每块屏 + 3s/5s 延时；截完复制路径并刷新出打开/文件夹/复制；热键 `alt+shift+s` 免开启动器）、`/pick`（热键 `alt+p` 即时取色 + 浮动取色台 + 历史 + HEX/RGB/HSL 切换）。均为 `kind=none` 纯前端。
- 测试：`tools/test-fe-plugins.mjs` 增 `MONITORS_FIXTURE`/`PIXEL_FIXTURE`/`CAPTURE_FIXTURE` 与 `screen`/`shortcuts`/`windows` 桩；settings 桩改为**内存 KV**（可验历史读写闭环）；**支持包内相对导入**（`.ts` 递归转译，`.tsx` 返回空模块——solid JSX 需编译期，故可测纯逻辑抽到 `.ts`，如 `pick/fe/src/color.ts`）；新增 shot/pick 用例。
- 验证：`plugin:test:fe` **15/15**、`plugin:test` **12/12**、`tsc --noEmit` ✅、`cargo check --workspace --all-targets` ✅、`deploy-portable-plugins` → **27 个**（12 LLP + 15 纯前端 manifest）。
- ⚠️ **`cargo test -p ll-host` 在本机跑不起来**：测试二进制加载期报 `STATUS_ENTRYPOINT_NOT_FOUND`（0xc0000139），Windows 链接/加载环境问题（项目门禁是 `npm run check`，本就不含 `cargo test`）。已记入 roadmap §11.6。
- 仍未做：全屏遮罩式取色 / 区域框选截图（`ViewSpec` 缺 `fullscreen`/`transparent` 声明位，宿主也无"窗口跟随光标"）、`ctx.fs`/`ctx.dialog`。

## 插件交互体验评审（产出 `docs/plugin-ux-review.md`）
- 结论：**功能广度够了，桌面级交互形态太窄**。A/B 组交互评级 B，C 组 C+，`/shot` 是 C。
- 🔴 P0-1 **截图复制的是路径不是图片**（`shot/fe/src/index.ts:122` `ctx.clipboard.write(shot.path)`）。Snipaste/ShareX/Win+Shift+S/PixPin 无一例外给图片本体。建议 `svc.screen.capture` 加 `toClipboard:true`，宿主走 arboard 写图片（约 20 行，插件零改动）。
- 🔴 P0-2 **无区域框选**，根因 `ViewSpec` 缺 `fullscreen`/`transparent`。这是解锁框选截图 + 遮罩取色的**唯一开关**；新增窗口仍须登记 `capabilities/default.json` 的 `windows`。
- 🟡 P1 **C 组需两次回车**（query 只渲染「查询」项）。根因是壳层对插件 `query()` **逐键调用无防抖**（`App.tsx:218` 直调，`searchRegistry` 那条才有 50ms 防抖 `:270`）。**不要在插件层硬改**，建议壳层加可选 `queryDebounceMs` 声明字段。

## `/find` 技术选型定案：实测 Everything SDK 可直接调用（RK-03 结论）

**实测环境**：本机 Everything 1.4.1032（`C:/Program Files\Everything\Everything.exe`），用户实例 pid 15240、`dbLoaded=true`、非管理员。用官方 `Everything-SDK.zip` 里的 `Everything64.dll`（91KB）经 ctypes 实测通过。

**结论：能直接调用，且不需要自己读MFT。** 查询耗时 7~35ms，`Cargo.toml` 命中 656 条、`size:>500mb` 命中 405 条。

### 关键 API 事实（都是踩出来的，别重推）
- `Everything_Reset()` → `SetSearchW()` → `SetMax()` → `QueryW(wait=True)`，**漏掉 Reset 会沿用上次的搜索词**。
- 结果索引**从 1 开始**，0 是无效索引（读它返回 0 长度）。
- ⚠️ **必须 `Everything_SetRequestFlags(NAME|PATH|SIZE|DATE_MODIFIED|ATTRIBUTES)`**，否则 size/mtime 全返回 0/None。请求标志位：NAME=1 / PATH=2 / SIZE=0x10 / ATTRIBUTES=0x20 / DATE_MODIFIED=0x40。
- ⚠️ **`GetResultDateModified` 返回 Windows FILETIME（1601 纪元）**，不是 Unix 时间戳。当Unix 用会得到 1970 或直接抛错。
- ⚠️ 通过 ctypes/Rust FFI 读 `GetResultFullPathNameW(i, buf, len)` 时缓冲区要显式转成 `LPWSTR`，直接传 buffer 会**静默返回 0**（不报错）。
- DLL 是 **per-thread 状态**（搜索词/结果游标），并发查询必须加锁；SDK 文档声称 thread safe 指 IPC 层。
- 慢查询要用 `QueryW(FALSE)` + 自建 reply window 收 `RegisterWindowMessage("EVERYTHING_IPC_REPLY")` 回调，不要阻塞主线程。

### 选型对比（回答 RK-03）
| 方案 | 结论 |
|---|---|
| **Everything SDK DLL**（推荐） | 免管理员、免 NTFS 限制（支持 ReFS/FAT/网络盘）、毫秒级。代价：要求用户装 Everything。DLL 91KB 可随插件分发，但**许可需确认**（SDK 页面未写明可再分发） |
| 裸 WM_COPYDATA IPC | 同样可用但要手搓 reply window + 结构体解析（我实测同步模式只回命中数不回落列表，必须 reply window），收益为零 |
| 自己读 MFT + USN Journal | 免外部依赖，但要管理员权限、仅 NTFS、代码量大得多。除非要做"不依赖 Everything 的开箱即用"，否则不值得 |
| `es.exe` 命令行 | 需带外部 exe 且要解析 stdout/CSV，不如 DLL |
| HTTP/ETP 服务器 | 本机实测 `etp_server_enabled=0`，且 Everything 的 HTTP 服务器**必须 GUI 里手动勾选**，改ini 不生效 —— 不适合做默认路径 |

### 推荐的落地形态（待实现）
`/find` 作为 **LLP 插件**（`plugins/find`，`kind: llp`）：优先动态加载 `Everything64.dll`，找不到则回退到提示"未检测到 Everything"并给安装引导。宿主侧需要一个 `svc.everything.query` 之类的能力或让 LLP 直接 Win32 FFI（后者更符合"一切皆插件"，不污染宿主）。

- ⚠️ **`GetResultFileNameW` / `GetResultHighlightedFileNameW` 返回垃圾内存**（实测 1966691184 这种明显不是长度的值），因为它们走本地缓存、不支持 `(NULL,0)` 问长度。**只能用 `GetResultFullPathNameW`**，文件名从路径切。高亮名放弃。
- ⚠️ 请求标志位以 SDK 的 `Everything.h` 为准，我第一次凭印象写错了两个：正确的 `ATTRIBUTES=0x100`（不是 0x20）、`HIGHLIGHTED_FILE_NAME=0x2000`（不是 0x100）。
- ⚠️ **结果索引从 1 开始，但 idx0 也是有效结果** —— 真正的上界是 `GetNumResults()`，`idx >= num` 才返回 0。
- ⚠️ DLL 查找路径别算错层：`plugins/find/everything.py` 的插件根是 `dirname(__file__)`（**只退一层**），我最初写了 `dirname(dirname())` 退到 `plugins/` 找不到 bin/。
- ⚠️ `fmt._shorten_middle` **不能按字符硬切路径**：会把 `averylongdirectoryname` 砍成 `averylongdirectorynam...e`，半个词既认不出也搜不了。改为按 `\` 分层保留头 2 层 + `...` + 尾 2 层。测试抓到了这个。

### 壳层/协议层的坑（跨插件通用）
- ⚠️ **壳层 `queryText` 是 trigger 之后所有 token 的原样拼接**（含子命令），而 `args` 又把第一个 token 挖走当 `subcommand`。所以 LLP 插件**不能**把 `args` 再拼回 `keyword`（会重复），只能从整串里剥控制词。
- ⚠️ 控制词剥离不能简单"删掉 desc/asc/limit 及其后一个词" —— 字段名（size/dm/name）完全可能就是用户想搜的词。判定依据必须是**参数合法性**：desc/asc 的参数必须是已知排序字段名，否则 `desc` 本身也留在搜索词里。
- ⚠️ 外部插件（LLP）原来拿不到 `queryDebounceMs`，`/find` 会被逐键打 IPC。已给 `ExternalCommandSpec` 加 `query_debounce_ms` 并在 `commands.rs` 的 `plugin_list` 透传，`externalPlugins.ts` 据此设置。manifest 里声明 `queryDebounceMs: 280`。

## /find 跨平台：新增 Linux 后端（22:46~23:2x）
**为什么不用 fzf**（用户曾问Linux 下用 fzf 实现）：fzf 是**终端 TUI 模糊过滤器**，要抢占终端自绘界面；LLP 插件只能回 JSON、面板由宿主统一画。且 fzf 不负责候选来源、没有元数据——两头都得自己补。对标 Everything 的其实是 plocate 这类索引工具。

**新增文件**
- `plugins/find/query.py` —— 纯逻辑：表达式解析（ext/size/dm/dc/da/name/path/type）+ 体积/时间单位换算 + 相关性打分。不碰 subprocess，故 Windows 上也能单测。
- `plugins/find/locate.py` —— Linux 后端，接口与 `everything.Everything` 完全一致（search/db_loaded/version）。
- `plugins/find/find.py` —— 改为 `get_backend()` 按 `os.name` 分派；`backend_label()`/`unavailable_hint()` 给平台化文案。
- `plugins/find/format.py` —— `build_footer(..., source=)`、`build_usage(..., syntax=)` 参数化，**去掉硬编码的 "Everything"**。

**分层策略**：plocate（索引）→ fd（并行遍历）→ find（兜底）。locate 库**只有路径没有元数据**，故只对截断后的前 N 条做 `os.stat()` 补 size/mtime，这样 `size:`/`dm:` 语法不退化。
**排序 code 与 everything.py 数值对齐**（SORT_SIZE=3 / SORT_DATE_MODIFIED=11），`find.py` 的 SORT_ALIASES 两端通用，有测试守着。

### 踩坑（都是静默失败，命令不报错只是返回空）
1. ⚠️ **后端探测不能只看 `which locate`**：Git Bash / MSYS 自带 GNU findutils 也叫 `locate`，只认 `-d/-r`，给它 `-i/-l/--all` 直接报错。原先 `probe()` 只看退出码，它返回 1（无结果）被误判为"索引可用" → 真查询永远空 → **/find 在该机器上完全失效**。改为用 plocate 专属参数组合探测。
2. ⚠️ **find 不支持嵌套括号**：`( -type f ( -name '*.rs' ) )` 报 `invalid expression; I was expecting to find a ')'`。find 不是递归下降解析器，「且」只能靠空格并列的隐含 `-a`：`find ROOT \( -type f -a -name '*.rs' \) -print`。
3. ⚠️ **`-quit` 不能用**：MSYS/BSD find 对 `-quit` + 括号子句组合处理不一致，Windows 自带 find.exe 加了只回 1 条（常是根目录本身）。改为一次性列出、上层按 cap 截断。
4. ⚠️ **索引与遍历是叠加不是二选一**：locate 库由 `updatedb` 定时刷新，新建文件还不在库里。索引返回空时仍要跑遍历兜底，否则用户刚保存的文件永远搜不到。
5. ⚠️ **点开头文件的扩展名**：`.gitignore` 的 ext 是 `gitignore`（与 Everything 一致），不能因 `rfind('.')==0` 判成"无扩展名"。
6. ⚠️ **不要把路径词推给 fd**：`--full-path` 的 pattern 是正则，而 Everything 语义是子串匹配，搜 `a.b` 会变正则、搜 `a b` 会被拆成两个 pattern。只推 ext/size/mtime 这类无歧义的结构化过滤。
7. ⚠️ **未知 `key:value` 必须降级为字面量**（`https://x` 的 key 是 https 不是字段名），绝不静默丢用户输入。

**测试**：`tools/test-find-logic.py` 31 → **83 组**（新增 TestQueryParse/TestParseSize/TestParseTime/TestMatchPath/TestMatchStat/TestRelevance/TestLocateBackend/TestFindExpression/TestLocateProbe/TestIndexAndTraversalMerge/TestPlatformDispatch）。`locate.py` 的 find 表达式与探测逻辑都有结构断言防回归。
`LocateIndex(roots=, backend_cls=)` 的 `backend_cls` 只给测试强制指定后端用（Windows 上没有 plocate/fd）。
**验证**：83/83 · LLP 13/13 · fe 17/17 · tsc 通过 · 临时目录端到端 9 组全通过。Windows 端 Everything 路径无回归。

## /pomo 桌面挂件 + 桌面壁纸层能力（22:57~23:5x）
用户需求：`/pomo start` 新建番茄钟时**自动在桌面显示倒计时挂件**，并要支持贴到系统桌面（Windows + Linux）。确认后方案=**两者都要**（默认置顶浮件 + `/pomo pin` 尝试壁纸层）。

### 宿主新增能力（这是"主程序提供建窗接口 + 注入插件界面"的落点）
- `src-tauri/crates/ll-host/src/desktop.rs`（新模块）：把窗口挂到**壁纸层**。
  - Windows：`SetParent(win, WorkerW)`，先向 Progman 发 `0x052C` 让 Explorer 生成承载壁纸的 WorkerW，再 `FindWindowW` + `GetWindow(GW_HWNDNEXT)` 枚举兄弟窗口。
  - Linux X11：`xprop -id <xid> -f _NET_WM_WINDOW_TYPE 32a -set _NET_WM_WINDOW_TYPE _NET_WM_WINDOW_TYPE_DESKTOP`。不引x11 crate（会拖 Xlib 依赖且 Wayland-only 机编译失败）。
  - **Wayland：做不到**，必须如实返回 `unsupported` —— z-order 由 compositor 独占管理，应用无权指定（Wayland FAQ 明确列为 "Not supported"）。这是安全设计不是 bug。
- `ll-plugin-api`：`WindowApi` trait 加 `attach_desktop(label)` / `desktop_supported()`；新增 `DesktopAttachStatus`/`DesktopAttachResult`（**`on_wallpaper` 是 UI 唯一判据**，false=降级为置顶浮窗，插件必须如实告知用户）。
- `services.rs::dispatch_svc` 加 `svc.window.attachDesktop` / `svc.window.desktopSupported`。
- ⚠️ 取原生句柄**不能用 `WebviewWindow::hwnd()`**（`cfg(windows)` 才有，跨平台编译不过），要用 `raw_window_handle::HasWindowHandle::window_handle(&w)` 再 `.as_raw()`。Xlib 与 Xcb 的 id 字段都叫 `window` 但是**不同 Rust 类型**，不能写成 or-pattern。

### pomo 插件
- `plugins/pomo/fe/`（新，纯前端包）：`timer.ts`（倒计时纯逻辑）+ `widget.tsx`（视图）+ `widget.css` + `index.ts`（注册视图）。
- manifest 加 `views[widget]`（240×88 无框置顶）+ `windows` 权限；**`capabilities/default.json` 必须登记 `pomo-*`**，否则死窗。
- 交互按用户选：纯显示 + **悬停出按钮**（常态不占视觉空间）；`/pomo start` 自动弹出。

### 跨进程状态（关键设计）
挂件是独立 Webview 窗口，与sidecar 是不同 JS 上下文，拿不到其内存。双向通道都走 **settings KV**（宿主强制 `${pluginId}.` 前缀、跨进程共享）：
- 正向：sidecar start/stop/到点时写 `target`/`label`/`minutes`，挂件每秒轮询（1s）。
- 反向：挂件按钮写 `cmd=pause:<ts>` / `stop:<ts>`，sidecar 的 `_cmd_loop` 每 0.5s 消费后**清空**（不清会重复执行；带时间戳后缀防 KV 判"未变更"丢写）。
- ⚠️ **`ctx.call('plugin.x')` 到不了 sidecar**（call 只能打宿主 svc.* 命名空间），`events` 也是单向 emit。这两条路都不通，别再试。

### ⚠️ 踩坑：多线程读 stdin 会抢响应行（严重）
sidecar 里主线程（处理宿主请求）和命令线程（消费挂件按钮）都会发 svc 并各自 `sys.stdin.readline()`，**后读的会把别人的响应取走** → 表现为"暂停按钮偶发没反应"，极难排查。
修法：**单一 reader 线程** `_reader_loop` 读所有行，按有无 `method` 分流（`method` → inbox 给主循环；否则按 `id` 派发给 `_await` 等待方），主循环改从 `_inbox_take()` 取消息。
配套：`_await` 必须带超时（宿主卡住时不该挂死）；`fire()` 的无主响应会堆在 `_pending`，**必须设 `_PENDING_MAX=64` 上限**否则长时间计时会缓慢内存泄漏。
（我写测试宿主时又犯了同一个错——`_pump` 和 `relay` 两个线程各读一次 stdout，直接超时。）

## /pomo 挂件三个真机 bug 修复（23:30~23:5x）
用户反馈：①挂件有左右下边框 ②时间是 00:00 没有倒计时进度 ③点击关闭关不掉窗口。

### ① 00:00 无进度 —— **秒/毫秒混用（最隐蔽）**
- sidecar 用 Python `time.time()`，写进 settings 的 `target` 是**秒级**（~1.79e9）；
  而 `deriveView` 要拿它跟 `Date.now()`（**毫秒** ~1.79e12）相减。
  → `remainingMs` 恒为巨大负数 → 永远命中 `remainingMs <= 0` 分支 → 恒显 00:00、进度恒 1。
- **全程零报错**，且两边都是 number，TS 查不出来，只有真机看倒计时才能发现。
- 修法：`timer.ts` 新增 `normalizeTargetMs()`，按量级自动判定（<1e11 视为秒级×1000）。
  **不写死 ×1000**：settings 是持久化的，将来 sidecar 改毫秒或用户留旧数据，
  硬编码会再次静默出错且方向相反。阈值 1e11 的依据：秒级到 2286 年才到 1e10，
  毫秒级 1973 年后就超 1e11，中间留三个数量级余量。
- ⚠️ 该函数放 `timer.ts` 而非 widget.tsx —— **.tsx 无法被测试加载**（需编译期），
  可测逻辑必须在 .ts（项目约定）。已加回归测试含端到端断言（归一后必须 25:00 而非 00:00）。

### ② 左右下边框 —— 全局 !important 底色 + 不透明窗口
- `index.html` 有全局 `html,body,#root{background-color:#1a1d24 !important}`，
  **!important 压过插件普通CSS**。挂件窗口不透明 → 这条底色填满窗口 →
  `.pw-root` 的 border-radius 切出的四角露出矩形角 + border 只画左右下 → 就是看到的"边框"。
- 修法：① manifest 加 `transparent: true`（宿主 `if spec.transparent { builder.transparent(true) }`
  已支持，`shot` 插件早就在用，Windows 上验证过）；② widget.css 用 `!important` 强制清底色；
  ③ **把背景/圆角/边框从根元素挪到内层 `.pw-card`** —— 根元素铺满窗口时画圆角没意义。
- 教训：插件视图想用圆角卡片，必须让**窗口本身透明**，否则圆角永远切出异色角。

### ③ 关不掉窗口 —— 三重原因
1. `stop()` 按钮提示写"停止**并收起**"，但代码只写 settings，**根本没有 close 调用**。
   挂件 `decorated:false` + `skip_taskbar` → 用户找不到系统关闭按钮，✕ 是唯一出口却没关窗。
2. `capabilities/default.json` **缺 `core:window:allow-start-dragging`** → 拖动会静默失败，
   用户想挪开它时拖不动，体感就是"窗口卡死/关不掉"。已补。
3. UI 语义混淆：收起（计时继续）与停止（终止）应是两个动作。已拆成 `⌃`=dismiss /
   `✕`=stop，且 stop() 先关窗再sync（关窗会销毁 JS 上下文，之后调用不再执行）。
- 拖动绑在 `.pw-card` 的 mousedown，用 `closest('.pw-actions')` 排除按钮区，
  否则点按钮会顺带拖一下窗口。

**共同点**：三个 bug 全是**静默失败**（无报错、退出码正常），只有真机操作能发现。
这类"看起来能跑但结果是错的"问题，端到端/回归测试比读代码可靠得多。

## 窗口贴边定位泛化：新增 top-right（23:40~23:5x）
用户要求 pomo 挂件从右下角移到**右上角**。`WindowPosition` 原本只有 `BottomRight`。

### 改动
- `ll-plugin-api`：`WindowPosition::TopRight` +两个纯函数
  - `is_corner_position()`：这两个变体在宿主**两处**分支都要判断（建窗前 `visible(false)` 防闪烁、建窗后 `set_position`+`show`），漏一处就会"窗口在原点闪一下才跳到角落"。故抽函数而非到处 `matches!`。
  - `corner_origin()`：定位算术抽成纯函数才能单测（写错的话症状是"挂件一半在屏幕外"或"堆叠窗口互相盖住"，都是真机才看得出的静默错误）。
- `ll-host::services`：改为调`corner_origin`，`stack_offset` 只在 corner 定位时才计算。
- `pomo/manifest.json`：`position: top-right`，版本 0.3.0。

### ⚠️ 关键修正：`stack_offset` 方向随角落而变
原来 `stack_offset` 是**写死的正数**且只服务右下角，语义是"向上让位"（y 减小）。
右上角必须**向下**让位（y 增大）——直接套用会让堆叠的第二个窗口盖住第一个。已按角落分支。

### ⚠️顺带修掉 `/pomo pin` 的一个隐藏 bug
`desktop.rs` 挂壁纸层时 `SetWindowPos(hwnd, HWND_TOP, 0,0,0,0, SWP_NOACTIVATE|SWP_NOZORDER|SWP_SHOWWINDOW)`
—— **缺 `SWP_NOMOVE`**！`SetParent` 会把坐标系从屏幕改为相对 WorkerW壁纸层，
此处的 (0,0) 被应用就会把挂件甩到左上角，把宿主算好的角落位置覆盖掉。
症状：`/pomo pin` 之后挂件位置跑偏。已补 `SWP_NOMOVE`。
（这个 bug 之前不显眼，因为当时窗口在右下角、用户不易察觉坐标异常。）
