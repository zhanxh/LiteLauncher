## 实现形态选型（内置 Rust vs Python/LLP）
- 已补入 `docs/plugin-roadmap.md` §6。
- 关键机制：LLP 外部插件前端零代码——`src/core/externalPlugins.ts` 按 manifest 的 `command` 声明自动生成通用 `CommandPlugin`；参数自动映射 execute→{raw,subcommand,args,namedArgs}、search→{keyword,subcommand,args}、select→{id,metadata}。
- 内置 Rust：7+ 文件 + 3 处宿主接线 + 重编译主程序；无运行时依赖。LLP：2 文件（manifest.json + .py）+ 拷目录即装，但依赖目标机有 Python 3、不支持自定义 UI 窗口、串行会话 5s 超时、每插件常驻一个解释器进程。
- 结论：核心高频工具（含 `/hash`）→ 内置 Rust（零依赖、可进单 exe）；探测/可选/第三方（如 sysinfo）→ LLP Python；长期等 `svc:*` 纯前端形态收口。可用 LLP 快速试水 UX 再移植 Rust。

## 术语校正（重要）
- 用户明确：本项目**一切皆插件，不做"内置"**（所有功能走插件机制，禁止硬编码进壳层/宿主）。
- 注意仓库文档的既有叫法：开发指南 §1 把 `plugins/*/be`（随主程序编译、lib.rs 注册的 Rust 插件）称为**"编译期内置插件"**——这与用户口语里的"内置"含义冲突。已把 roadmap §6 标题/正文改为**"编译期插件（Rust）vs 外部插件（LLP）"**，并加术语对齐说明。
- 洞见：**LLP ≠ Python**——`backend.entry` 可指向任意可执行文件（支持 `node`、绝对路径），故外部插件也能用 Rust 编的独立二进制（零运行时依赖）；"用 Rust"也不等于"编译进主程序"。

## 宿主能力补齐（4 项，全部落地）
1. **`svc.db.migrate`** —— 兑现 `DbApi::migrate`（`execute_batch`），只对插件自己的库生效（`plugins/<id>/<id>.db`），故放行 DDL 无越权。
2. **`svc.clipboard.write/read`** —— 新增 `ll_plugin_api::ClipboardApi` + `PluginContext.clipboard`；宿主实现走 **`tauri-plugin-clipboard-manager` 2.4.2（底层 arboard）**，不用 webview 剪贴板。**写/读分权**：`clipboard:write` / `clipboard:read`。壳层 `AfterSelect.copy` 同步切到宿主命令 `clipboard_write`（`src-tauri/src/lib.rs`）。
3. **`svc.http.send`** —— 借道 `HttpApi::send_stream` 收集全文，**顺带拿状态码**，返回 `{status, body}`；仍走 `net:<host>` 白名单。`headers` 兼容 `{"K":"V"}` 与 `[["K","V"]]`。
4. **`svc:*` 纯前端插件形态（`backend.kind="none"`）** —— 三处协同：
   - 宿主：`handle_svc` 提炼为公共 `services::dispatch_svc`（LLP 反向请求与前端 `ctx.call('svc.*')` **共用同一分发器**）；`plugin_call` 把 `svc.*` 当**宿主保留方法名空间**优先拦截，不查后端分发表；新增 `SvcBackend`（kind=none）；`register_external_plugins` 接受 `kind="none"`。
   - 权限门控：已注册插件按 `manifest.permissions`；未注册（只随前端包编译进来）退回 `shell_safe_manifest`（仅 settings/clipboard:*/notifications/events，**db/process/net 一律拒绝**）。
   - SDK：`ctx.settings/clipboard/log/notify/events` 同名属性包装 `svc.*`；新增 `isHostAvailable()`。
   - 开发期宿主 `#[cfg(debug_assertions)]` **自动扫描仓库 `plugins/`**（`env!("CARGO_MANIFEST_DIR")/../plugins`），免每次 plugin:install，且让 kind=none 能读到 manifest。
   - 工具：`install-plugin.mjs` / `deploy-portable-plugins.mjs` 支持 kind=none（**只部署 manifest.json**，fe 已在应用包内）。

## 落地：C 组网络插件（5 个，纯前端 TS）
- 形态：既然 `svc.http.send` 已落地，网络类**无需 Python**，全部做成 `kind=none` + `fe/src/index.ts`，仅 `manifest.json` 声明 `net:<host>`。零宿主改动、零重编译。
- 5 个：`/weather`(wttr.in) `/fx`(open.er-api.com) `/ip`(ipwho.is) `/dict`(api.dictionaryapi.dev, +process) `/tr`(api.mymemory.translated.net)。
- **关键设计（网络插件范式）**：壳层 `query()` 逐键调用且**无防抖**（App.tsx §3.2），故**绝不把请求放进 query**。统一：query 命中缓存才渲染，否则只给一条「查询」项（`metadata.fetch`=缓存键）→ `onSelect(查询项)` 抓取+写缓存+返回 `{refresh:true}` → 壳层重跑 query 命中缓存刷新面板 → `onSelect(结果项)` 回 `{copy}`。TTL 5–30 分钟。
- **SDK 补 `ctx.http`**（`lps.ts`，与 settings/clipboard 同构）：`send({method,url,headers,body})→{status,body}` / `get` / `json<T>`（非 2xx 或非 JSON 抛可读错误）。`/dict` 用 `send` 才能区分 404 未收录与网络异常。
- 服务实测取舍：可达 → wttr.in / open.er-api.com（`time_eol_unix=0`）/ ipwho.is / dictionaryapi.dev / mymemory；不可达（000）→ ipify、myip.com、coingecko、translate.googleapis、tinyurl、cloudflare-doh、dns.google；需 key → 快递 API。故 `/crypto`(行情) `/short` `/dns` `/express` 暂缓。
- wttr.in 服务端 `lang=zh` **实测不翻译**（仍回 Sunny），故在插件内自建英文天气词 → 中文映射 + 风向 16 方位中文表。
- 测试：`tools/test-fe-plugins.mjs` 桩增加 **`svc.http.send` 域名 fixture**（函数形式可模拟 404）；新增 `drive:true` 用例走完整范式，断言真实解析（`Sunny→晴`、`100 USD = 670.582 CNY`、`AS15169`、`/həˈləʊ/`、`你好世界`、dict 404 分支）。

## 落地：D 组能力包（屏幕捕获 + 全局热键）+ `/shot` `/pick`
- 宿主新增两项能力：`ScreenApi`（`screen` 权限，xcap 0.9 + image(png) + Tauri `AppHandle::cursor_position()`）与 `ShortcutApi`（`shortcut:<accel>` 权限，tauri-plugin-global-shortcut + 宿主自建仲裁表）。`PluginContext` 增 `screen` / `shortcuts`。
- `dispatch_svc` 新增：`svc.screen.list|cursor|pixel|capture`、`svc.shortcut.register|unregister|list`、**`svc.window.open`**（纯前端插件唯一的开窗途径）。`PluginErrorCode` 增 `Conflict`。
- **热键协议**：宿主按 `shortcut:<accel>`（逐条、无通配）放行 → 进程级 `accel→pluginId` 表先到先得仲裁（冲突回 `conflict`）→ 触发时 `emit("plugin-shortcut", {pluginId, accel})`。插件只听事件，拿不到按键流。解析/挂载失败都回滚登记。白名单校验放在 `AppHandle` 校验之前，便于无 GUI 单测。
- **关键坑（务必记住）**：纯前端插件新增视图窗口（标签 `<pluginId>-<viewId>`）**必须**同步加进 `src-tauri/capabilities/default.json` 的 `windows` 白名单，否则该窗口权限为零 → `plugin_call` 被拒、面板变死窗。本轮加了 `pick-*` 与 `core:window:allow-outer-position`/`allow-outer-size`。
- **坐标系**：对外统一桌面全局物理像素；但 `xcap::Monitor::capture_region` 要的是**显示器内相对坐标（u32）**，所以宿主先 `hit_rect` 定位显示器再减原点（这层换算不能散到插件里）。`x()`/`y()` 是 i32、`width()`/`height()` 是 u32。
- **截图避让**：`hideWindows:true` → 隐藏所有可见 LiteLauncher 窗口 + 额外 160ms 合成器宽限 → 截图 → 复原并回焦。`delayMs` 宿主硬上限 10s。
- **放大镜不传图片**：`svc.screen.pixel {radius}` 回 `#RRGGBB` 方格数组（`cols/rows/cells/center`，贴边自动裁剪），前端 CSS 网格铺出来即硬边像素放大；省掉 PNG 编码 + base64（约 33% 膨胀）。半径上限 32。
- **SDK**：`ctx.screen`（list/cursor/pixel/capture）、`ctx.shortcuts`（register/unregister/list/**on**）、`ctx.windows`（open）。**`ctx.shortcuts.on(accel, cb, {scope})` 默认 `scope:'main'`**——每个窗口加载都会跑一遍全部插件 `setup()`，不区分上下文则热键会被执行两次；取色台显式传 `{scope:'any'}`。
- **多窗口协同**：取色台与主窗口是两个 JS 上下文，靠插件私有 KV 共享（`pick.history`、`pick.panelOpen`）；面板开着时主窗口热键处理器读到 `panelOpen` 就让位，避免一次按键既复制又关窗。
- **取色台冻结**：`outerPosition/outerSize` 与 `svc.screen.pixel` 回传的采样坐标比对，光标进面板即停采样（否则采到面板自身颜色）。一次宿主调用同时拿到位置+颜色+放大镜，7Hz 轮询。
- 插件：`/shot`（主项=光标所在屏 + 每块屏 + 3s/5s 延时；截完复制路径并刷新出打开/文件夹/复制；热键 `alt+shift+s` 免开启动器）、`/pick`（热键 `alt+p` 即时取色 + 浮动取色台 + 历史 + HEX/RGB/HSL 切换）。均为 `kind=none` 纯前端。
- 测试：`tools/test-fe-plugins.mjs` 增 `MONITORS_FIXTURE`/`PIXEL_FIXTURE`/`CAPTURE_FIXTURE` 与 `screen`/`shortcuts`/`windows` 桩；settings 桩改为**内存 KV**（可验历史读写闭环）；**支持包内相对导入**（`.ts` 递归转译，`.tsx` 返回空模块——solid JSX 需编译期，故可测纯逻辑抽到 `.ts`，如 `pick/fe/src/color.ts`）；新增 shot/pick 用例。
- 验证：`plugin:test:fe` **15/15**、`plugin:test` **12/12**、`tsc --noEmit` ✅、`cargo check --workspace --all-targets` ✅、`deploy-portable-plugins` → **27 个**（12 LLP + 15 纯前端 manifest）。
- ⚠️ **`cargo test -p ll-host` 在本机跑不起来**：测试二进制加载期报 `STATUS_ENTRYPOINT_NOT_FOUND`（0xc0000139），Windows 链接/加载环境问题（项目门禁是 `npm run check`，本就不含 `cargo test`）。已记入 roadmap §11.6。
- 仍未做：全屏遮罩式取色 / 区域框选截图（`ViewSpec` 缺 `fullscreen`/`transparent` 声明位，宿主也无"窗口跟随光标"）、`ctx.fs`/`ctx.dialog`。
