## build.cmd / build.sh 健壮性修复（新机器报 failed to resolve import）

- 现象：换台式机 `build.cmd` 报 `failed to resolve import "@kobalte/core/select"`。
  根因是 node_modules 目录"存在但残缺"（拷贝/网盘同步/安装中断），旧脚本只判断
  `if not exist node_modules` 就跳过 `npm install`。
- 修复：依赖检查改为探测前端实际会 import 的包
  (`node_modules/@kobalte/core/package.json`)；前端构建失败给出提示
  `rm -rf node_modules && npm install`。提交 `29af9e6`。
- ⚠️ build.cmd 必须 ASCII-only（cmd.exe 解析 UTF-8/GBK 会乱码），提示文案用英文。
- 排查套路：先看 `dist` 体积/transformed 模块数是否正常（缺依赖时 bundle 会明显变小）。

## Node 版本门禁（F: 机器编译报错）

- 报错 `??= SyntaxError` + `cpSync not exported`：F: 机器 Node 过旧（Vite 8 要求
  20.19+/22.12+）。**隐蔽坑**：旧 Node 下 vite 崩溃但 npm 仍 exit 0，build.cmd
  继续跑，把过期前端嵌进 exe 静默产出废品。
- 修复（`37b88ad`）：build.cmd/build.sh 增加 Node 版本门禁（解析 `node -v`，
  比较 major/minor：>22 OK；==22 需 ≥12；==20 需 ≥19）；构建后校验
  `dist/index.html` 存在；package.json 声明 `engines.node >= 20.19`。
- 批处理数值比较用 `if %A% GTR/EQU 22`；括号块内 echo 的文本**不能含裸 `(` `)`**；
  build.cmd 编辑后必须重新规范化为 CRLF（python 字节级替换）。
- 版本判断逻辑用模拟版本号（v14→v24 共 9 例）在临时 cmd 里验证过。
