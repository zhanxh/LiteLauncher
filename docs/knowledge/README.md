# 知识库

> 沉淀"下次还会用到"的结论：踩过的坑、验证过的事实、对外部资料的整理。
> 与 `docs/records/` 的区别：records 是某个时点的快照，knowledge 是**持续有效**的结论。

## 目录

| 目录 | 放什么 | 命名 |
| :--- | :--- | :--- |
| `lessons/` | 踩坑与经验：现象 → 根因 → 判据 → 处理 | 主题名，`kebab-case`，无时间戳 |
| `reference/` | 外部资料整理：协议、平台行为、第三方文档要点 | 同上 |

## 什么时候写

- 一个问题**第二次**出现，或排查超过 30 分钟；
- 某个平台/工具的行为与直觉相反（Windows 窗口、GTK、WebView2、Node 版本…）；
- 设计文档里被反复问到的一个判断依据。

不写：一次性的任务细节（进任务日志）、能从代码直接读出来的事实。

## 一条经验的结构

```markdown
# <一句话结论>

- 日期：YYYY-MM-DD
- 适用版本：<version / 平台>
- 关联：<提交号 / 设计文档 / 任务>

## 现象
（用户看到什么、日志里有什么）

## 根因
（真正的原因，不是表面症状）

## 判据
（下次怎么快速确认是同一个问题，一条命令或一个现象）

## 处理
（怎么修；如果是取舍，写清代价）
```
