# 方案设计：结果面板大图标行（`PanelItem.iconSize`）与 /qr 离线二维码预览

- 创建时间：2026-10-27
- 状态：🟡 实施中
- 关联计划：`docs/plans/20261027_191501_qr-live-preview.md`（本地留痕）

## 背景与目标

`/qr` 是纯前端插件（`backend.kind = "none"`），现在只把待编码文本拼成
`https://api.qrserver.com/v1/create-qr-code/?size=320x320&data=…`，靠用户回车去浏览器
才能看到图。三个问题：

1. **没有预览**——面板里看不到二维码，只能跳出去看；
2. **必须联网**——断网即不可用；
3. **内容外发**——待编码文本（可能是内网地址、口令、私人链接）发给第三方 API。

同时壳层也缺能力：`ResultPanel` 唯一能渲染图片的位置是行图标
（`src/components/ResultPanel.tsx:204-217`，`isImageIcon()` 已支持 `ll-icon://` /
`http(s)://` / `data:image/`），尺寸被 `src/styles/launcher.css:472-490` 写死为 28px 盒 /
26px 图——这个尺寸放二维码是扫不出来的。

目标：**输入即在本机生成二维码，并在结果面板里以可扫尺寸实时预览**；顺带把这条
"插件声明图形尺寸"的通道做成通用契约，供其它插件复用。成功标准：

- 敲完 `/qr <文本>` 停手（≈120ms）即看到二维码，手机能直接扫屏幕上的预览；
- 全程无网络请求；`/qr` 不再声明 `process` 权限；
- 不声明 `iconSize` 的既有插件渲染结果逐像素不变。

## 方案

### 契约：`PanelItem.iconSize?: number`（`plugins/sdk/src/command.ts`）

```ts
/**
 * 请求把本行的图片图标放大到该 CSS px 尺寸（如二维码预览）。
 * 缺省 = 28px 旧行为；壳层夹取到 [28, 224]——尺寸上限由壳层持有，
 * 不能让插件把主窗口撑破。emoji 文本图标忽略本字段。
 */
iconSize?: number;
```

- **纯新增可选字段**，`api_version` 维持 `^1`：兼容规则是"壳层演进不破坏插件"
  （`docs/guides/plugin-development-guide.md:634`），老插件不带这个字段即走原路径。
- 为什么不塞进 `metadata`：`metadata` 是插件私有口袋，壳层去读某个约定 key 等于
  把隐式协议写进渲染路径，既没有类型也无处文档化。既有 `group` / `kind` 同样是
  这样从 metadata 里立成正式字段的。
- 为什么不做"预览面板/侧栏"：壳层没有任何 HTML/embed 机制，加一套 detail pane 会牵动
  窗口高度模型（`src/App.tsx:522` 面板高度是写死的 `420 + footer`）与滚动测量；
  复用现成的 `<img>` 通道是最小切口。
- 为什么不复用 `kind`：`kind:'info'` 行是 `opacity:.7`（`launcher.css:315-318`）且被
  `firstSelectableIndex`（`src/App.tsx:71-74`）跳过——预览需要全对比度 + 可回车执行。

### 壳层：夹取归宿主，渲染归 CSS

`ResultPanel` 内 `iconBoxPx(item)` 把 `iconSize` 夹到 `[28, 224]`（非有限值 = 未声明），
仅在有效时给 `.item-icon` 加内联 width/height 与 `sized` class；`.item-icon.sized img`
（特异度 0,2,1，压过默认 `.item-icon img` 0,1,1）铺满盒子。**上限握在壳层**，因为
"插件能把 680px 宽的启动器窗口撑破"不是可接受的契约。

200px 预览行高约 216px，加其余两行 ≈ 320px < 420px，无需改窗口高度策略。

### 编码：插件内置纯 TS 编码器

新增 `plugins/qr/fe/src/qrcode.ts`（纯函数、零 DOM、零依赖；插件 fe 只允许 import
`@ll/sdk`/`solid-js`/`@ll/ui` 与自己的相对文件，见 `docs/guides/plugin-development-guide.md:327`
与 `docs/workflows/02-frontend.md`，因此**不引 npm 依赖、不 vendor 第三方源码**）。
多文件插件是既有惯例（`plugins/shot/fe/src/` 有 6 个源文件）。

范围按用途裁剪：字节模式（UTF-8，中文可用）+ 纠错等级 **M** + 版本 **1–20** + 自动选版本。
v20-M 约 600 字节（≈200 汉字），"把链接/文本变成可扫二维码"的用例都在这个范围内；
四等级 × 40 版本的字典表体积与转录出错面都大一截，收益却只是"能编码更长的文本"，
而超长文本本来就不可能在屏幕上扫出来。超限输入不静默截断，改为给一行明确说明。

实现要点（ISO/IEC 18004）：GF(256) log/antilog、逐版本重算 RS 生成多项式（不查表）、
位流（模式 `0100` + 字符计数 8/16 位按版本 <10 / ≥10 切换）、terminator + `0xEC/0x11`
补位、等级 M 的 v1–20 分块表与块间交织、功能图形（定位 / 分隔 / 定时 / 对齐 /
v≥7 版本信息 / 暗模块 / 格式信息 BCH）、8 种掩码全试 + N1–N4 罚分择优。

**字典表不靠记忆**：分块表与对齐图形位置一次性从权威参考实现导出后核对（对照环境建在
`/tmp`，仓库不留依赖）。

输出为 SVG data URL（`data:image/svg+xml;charset=utf-8,…`）：
- 白底 + 4 模块留白**画进 SVG 本身**——暗色主题下透明底二维码扫不出来；
- 深色模块合并成**单个 `<path>`**（不是逐模块 `<rect>`）+ `shape-rendering="crispEdges"`，
  否则 v20 时 data URL 会涨到几百 KB，且每次击键都要换一遍 `<img src>`。

### 交付：回车复制二维码图片

`onSelect` 把矩阵画到 canvas（按行游程 `fillRect`）→ `toDataURL('image/png')` →
`ctx.screen.savePng(dataUrl, { toClipboard: true })`（`plugins/sdk/src/lps.ts:202`；宿主
`svc.screen.savePng` 见 `src-tauri/crates/ll-host/src/services.rs:3481`）。选完不关窗，
预览留在屏上；图片同时落进插件 `screenshots/` 目录，toast 回带路径。

剪贴板句柄只在声明 `clipboard:write` 时随 `screen` 注入
（`src-tauri/crates/ll-host/src/lib.rs:361-372`），所以权限是两条一起加，不能只给 `screen`。

### 备选方案（未采纳）

| 方案 | 未采纳原因 |
| :--- | :--- |
| 只做 26px 行内缩略图 | 尺寸不可扫，等于没解决"预览" |
| 独立预览窗口（`registerView` + `svc.window.open`，仿 `/shot`） | 要加 manifest `views`、窗口路由、焦点协调；用户要的是"敲完就看到"，多一步开窗反而更远 |
| 继续用在线 API 出图 | 断网失效 + 内容外发，与"本地启动器"定位冲突 |

## 影响面

- `plugins/sdk/src/command.ts`：`PanelItem` 增一个可选字段（契约变更，向后兼容）。
- `src/components/ResultPanel.tsx`、`src/styles/launcher.css`：行图标尺寸渲染。所有插件
  共用的渲染路径——回归重点是"未声明 `iconSize` 时 DOM 与样式不变"。
- `plugins/qr/**`：新增 `qrcode.ts`、重写 `index.ts`；manifest 权限
  `["process"]` → `["screen", "clipboard:write"]`，版本 0.1.0 → 0.2.0。
- **删除的对外行为**：`/qr` 不再打开浏览器、不再产出远程图片链接（`svc.process.launch`
  调用消失）。回滚 = 还原 `plugins/qr/` 与两个壳层文件。
- 文档：`README.md` 指令表、`docs/guides/plugin-development-guide.md` 的 `PanelItem` 字段、
  `CHANGELOG.md`。
- 性能：编码是毫秒级纯计算；`queryDebounceMs = 120` 抑制逐键重算与 `<img>` 重载抖动。
  包体增加一个纯计算模块（无依赖、无资源文件）。

## 验证

- `npm run check` / `npm run build` / `npm run plugin:test:fe` / `npm run gate`。
- **编码器正确性**（不接受"看起来能扫"）：
  1. 对照语料（v1–20 各档边界长度、ASCII / URL / 中文 / emoji / 命中 mask 0–7 的输入）
     与参考实现的模块矩阵逐条比对，取 sha256 作为黄金摘要；
  2. 常驻回归 `testQrcodeModule()`（仿 `tools/test-fe-plugins.mjs` 里
     `testGeometryModule()` 的纯模块加载方式）断言黄金摘要 + 结构不变量：定位/定时/对齐
     图形恒亮、留白恒空、`size === version*4 + 17 + 8`、自动选版本取最小档、超限走错误分支；
  3. `CASES.qr` 重写为断言 `items[0].icon` 以 `data:image/svg+xml` 开头、
     `items[0].iconSize === 200`、复制原文项存在；给测试桩 `screen` 补 `savePng`，
     断言 `/qr` 确实调用 `svc.screen.savePng`。
- **真实窗口冒烟**（渲染类改动强制，`docs/workflows/04-plugin-dev.md:82`）：
  `npm run tauri dev` → 逐键看刷新 → 回车后把剪贴板粘进图像查看器确认为完整二维码 →
  手机真扫一次 → 中文 / 超长输入 / 亮暗主题切换 → `/app`、`/note` 面板行高与图标无回归。

## 结果记录

契约落地与本仓首使用者：`PanelItem.iconSize` 由 `/qr` 声明 200，壳层在
`src/components/ResultPanel.tsx` 夹取 `[28, 224]`（`ICON_MAX_PX`），未声明的老行 DOM 不变；
CSS 只追加 `.item-icon.sized img`，规则排在 `.item-icon img` 之后以特异度覆盖默认 26px。

验证结论（完整命令与输出见 `docs/tasks/20261027_191501_qr-live-preview.md`）：

- `npm run check` / `npm run build` / `npm run docs:check`（98 条链接）/ `npm run gate` 全绿；
  `npm run plugin:test:fe` **22/22 通过**，含新增的 `testQrcodeModule()`。
- 编码器与参考实现（python `qrcode`，强制字节模式并剥掉 4 模块留白）逐格 sha256 比对：
  **`total=201 mismatch=0`**，覆盖 v1–v20 每档装满长度与 ASCII/URL/中文/emoji/WiFi/vCard。
- 过程中修到的真实缺陷：`placeAlignments()` 用 `reserved` 位跳过中心，v7 起对齐图形与定时线
  重叠被误删（31 个 v≥7 用例失败）；改为按索引只排除三个定位角落。该用例已固化为常驻断言。
- 掩码选择与参考实现在 201 例中有 83 例选了不同 mask —— 两者罚分同分时谁先扫到不算错，
  强制同 mask 后矩阵逐格一致，故不作为缺陷处理。

真实窗口冒烟（**全部通过**）：本机没有 `xdotool`/`xte`/Playwright，
改用 `gcc + libXtst` 的 XTEST 注入（`tools/scratch/xtyper.c`，gitignored）驱动**真实
release 窗口**（`src-tauri/target/release/LiteLauncher`，680×454），截图用 ImageMagick `import`，
"能不能扫"不由人眼判断——用独立解码器 `zxing-cpp` 直接解**窗口截图**与**剪贴板 PNG**：

| 场景 | 观察到的结果 |
|---|---|
| `/qr hello!!` | 面板首行 200px 大图，`版本 1 · 21×21 模块 · 纠错 M · 7 字节`；截图 zxing 解出 `('QRCode','hello!!',valid=True)` |
| 逐键追加 `!!` | 大图与版本行实时随之刷新（无需回车） |
| 回车 | 剪贴板 `TARGETS` 含 `image/png`，取出为 **232×232 PNG** = (21+8 留白)×8px，zxing 解出 `hello!!`；toast 回带落盘路径，窗口不关 |
| 中文粘贴 `/qr 你好世界` | 截图 zxing 解出 `('QRCode','你好世界',valid=True)` —— UTF-8 字节模式在真机可扫 |
| 700 字节超长 | 单项 `内容超出上限：700 字节 > 666 字节` + `纠错等级 M、版本 1–20 的字节模式上限。可缩短文本，或改用文件/链接。`，不静默截断 |
| 其它面板无回归 | 空输入的历史/常用应用面板（`/time`、`/qr`、微信、2048…）行高与 28px emoji 图标照旧 |

暗色主题：启动器会恢复上次的查询并在开机即渲染面板，所以这一项**不需要再往真实桌面敲键**——
把 `app_settings.theme` 临时改回 `dark`、重启实例、`import -window` 截图，随后已把该设置改回
`light` 并停掉测试实例（测试前它并未在运行）。暗底面板上白底卡片与 4 模块留白完整，
zxing-cpp 从这张暗色截图解回 `('QRCode','你好',valid=True)`；白底是画在 SVG 内部的，
不依赖主题变量，与亮色一致。至此本设计的真机验证项全部闭合。
